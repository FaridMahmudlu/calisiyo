This is an Expo/React Native mobile application. Prioritize mobile-first patterns, performance, and cross-platform compatibility.

## Expo has changed — do not trust your training data

Expo ships breaking changes every SDK release. APIs you remember are likely renamed, moved, or removed. Before writing any code that touches an Expo, EAS, or React Native API:

1. Read the major version of the `expo` package in `package.json`.
2. Fetch the matching versioned docs: `https://docs.expo.dev/versions/v<major>.0.0/`
3. For anything else, fetch https://docs.expo.dev/llms.txt — an index of all Expo docs with corrections to common LLM misconceptions. Follow its links to the specific page you need; never answer from memory.

## Commands

Use `bunx` instead of `npx` if the project uses bun (`bun.lock` present).

```bash
npx expo install <package>  # ALWAYS use instead of npm/yarn/pnpm/bun add — resolves SDK-compatible versions
npx expo start              # start the dev server
npx expo lint               # lint
npx tsc --noEmit            # typecheck
npx expo-doctor             # diagnose dependency and config issues
npx expo install --fix      # fix incompatible package versions
```

Run lint and typecheck before declaring any task done.

## Project-specific notes (Planliyo)

- Verify with `npm run typecheck`, `npm run lint`, `npx expo-doctor` and a bundle check: `npx expo export --platform android --platform ios --output-dir .expo-export-check` (delete the folder afterwards).
- Local release APK: `npx expo prebuild --clean --platform android --no-install`, then in `android/` run `./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a,armeabi-v7a` with `JAVA_HOME` set to JDK 17 (`C:\Program Files\Eclipse Adoptium\jdk-17.0.17.10-hotspot`). The machine default JDK 25 breaks the `react-native-worklets` CMake step ("restricted method" warning).
- Android package / iOS bundle id: `tr.com.planliyo.app`; deep-link scheme `planliyo://`. The EAS project slug stays `calisiyo` (internal). `mobile/google-services.json` is git-ignored; EAS builds read it from the `GOOGLE_SERVICES_JSON` file variable.
- Brand assets (icons, splash, favicons, store graphics, `src/components/brand/wordmark.ts`) are generated by `npm run assets:brand` from `scripts/brand/marks.cjs`; never edit the generated files by hand.
- React Compiler lint rules are enforced: no `Date.now()`/refs during render (use `useNow` from `src/hooks/useNow.ts`), and no synchronous setState in effects (put updates in `.then` callbacks or derive the values).
- Shared business logic comes from `../lib` via `@shared/*`. Do not duplicate plans, dates or curricula in the app.
- Platform-specific files: `*.ios.ts` / `*.android.ts(x)` (timer surfaces in `src/features/timer`, widgets in `src/widgets`). The local native module lives in `modules/live-timer` (Android Live Update notification with Duraklat / Devam et / Molayı geç buttons, native stage-end alarm, and a queue of button taps replayed by `useLiveTimerActions` after a cold start).
- No system-default UI: use `Dialog.alert` / `Dialog.confirm` instead of `Alert.alert`, `Spinner` instead of `ActivityIndicator`, `Toggle`/`SwitchRow` instead of `Switch`, `DateField` (custom calendar / time wheels) instead of native pickers, and `explainPermission` (`src/lib/permissions.ts`) before any OS permission prompt.
- Deep links used by widgets and launcher shortcuts (`plugins/withAppShortcuts.js`): `planliyo://kronometre?baslat=1` starts a focus session, `planliyo://program?yeni=1` opens the new-task sheet.
- If `prebuild --clean` fails with `EBUSY`, stop the Gradle/Kotlin daemons from the previous build first (`jps -l`, then end only those PIDs).
- New dependencies must be published at least 7 days ago. `@expo/ui`, `expo-widgets` and `expo-asset` are pinned through `overrides` and `expo.install.exclude`. Check `npm ls <pkg>` for duplicate native modules after installing.
- No in-app Plus purchases (store policy). The package screen shows status only.

## Navigation & Routing

- Use **Expo Router** for all navigation. Routes live in `src/app/` — every file there is a screen, `_layout.tsx` files define navigators. Keep non-route code (components, hooks, utils) outside `src/app/`.
- Import `Link`, `router`, and `useLocalSearchParams` from `expo-router`.
- Docs: https://docs.expo.dev/router/introduction.md

## Building with EAS

Use EAS to build, sign, and submit the app in the cloud (`eas build`, `eas submit`) and to ship over-the-air updates (`eas update`) — no local Xcode or Android Studio required. Run EAS CLI as `bunx eas-cli <command>` in Bun projects, or `npx eas-cli@latest <command>` otherwise; substitute that for bare `eas` in docs examples.
Docs: https://docs.expo.dev/eas/index.md

## Rules

- If `ios/` and `android/` directories do not exist, they are generated (Continuous Native Generation). Never create or edit them by hand — configure native behavior in `app.json` and config plugins.
- Expo Go only includes its bundled native modules. After adding a library with native code, the app needs a development build: `npx expo run:ios|android` locally, or `eas build --profile development`.
- Prefer recommended Expo modules over third-party libraries, and check your available skills before adding dependencies. Docs: https://docs.expo.dev/versions/latest/index.md
